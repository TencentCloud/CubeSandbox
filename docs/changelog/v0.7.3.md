## 2026.10.12 Release v0.7.3

CubeSandbox 0.7.3 introduces a major feature along with multiple enhancements and bug fixes. 32 commits from 15 contributors.

### 🎯 Major Features

#### MCP support

Sandboxes can now run an MCP (Model Context Protocol) gateway, matching the E2B SDK's `mcp` create option:

- Pass `mcp` when creating a sandbox; once it is running, the Python / Node / Go SDKs start `mcp-gateway` inside it and hand back the MCP URL and token. A gateway that fails to start kills the sandbox, so a caller never gets a half-working one.
- The SDKs look for a template aliased `mcp-gateway`, falling back to `CUBE_TEMPLATE_ID`. The default sandbox image has no gateway, so build one from the reference implementation under `examples/mcp-gateway`; the [MCP Gateway Guide](https://cubesandbox.com/guide/mcp-gateway.html) covers the setup.

### ✨ Enhancements

#### Templates & Storage

- S3lvol hot upgrade: the I/O pause a sandbox pays during an upgrade drops from about 40 seconds to about 8, and volumes stay attached throughout (#1822).
- Cheaper cross-node restore on S3lvol: a restored sandbox reads its disk from the snapshot on S3 on demand instead of copying the whole disk to the node up front (an explicit decouple still makes a standalone copy). Deleting the source snapshot now waits until such volumes are gone (#1898).
- Creating a template from an image fails immediately when the target nodes are offline or don't exist — 0.08 s instead of minutes of pulling and unpacking (#1829).
- S3 volumes can authenticate with the node's instance role instead of a long-lived access key: set `CREDENTIALS=instance_role` and drop both keys. This applies to manual installs whose endpoint is an AWS one, and the role must be attached to every CubeMaster and Cubelet host, not just the node running the sandbox — see the [S3 Volume Guide](https://cubesandbox.com/guide/s3-volume.html) (#1751).

#### Lifecycle & Control Plane

- Pause is faster: the VM teardown at the end of a pause now runs in the background. A single pause is ~41% faster (150 ms → 88 ms for a 2 GiB sandbox), ~20% faster under concurrency 50; resume is unchanged (#1731).

#### Deployment & Runtime

- PVM host / guest kernel updated from 6.6.69 to 6.6.117 (#1852).

#### Web UI / CubeOps / Other

- Template cards in the Web UI now show the template alias, not just the raw ID (#1876).
- New blog posts: global hiring, and an enterprise secure execution plane for OpenClaw / DSH (#1884).

### 🐛 Bug Fixes

#### Lifecycle & Sandbox

- Fixed Info returning a paused sandbox without its metadata (labels, template, specs, volume mounts), present since v0.7.0: callers that identify sandboxes by label could no longer resume them, and Info and List disagreed (#1861).
- Fixed clones failing with `no more resource` right after a snapshot was created, when the node's heartbeat had not caught up yet (#1909).
- Fixed the template list hanging once the cluster had many templates (#1899); the list API and `cubemastercli tpl ls` also gained paging (`limit` / `offset`).
- Fixed sandbox resources (network tap, IP, volumes) being released while the sandbox process might still be running, which could break a live sandbox's network. Cleanups that keep failing now alert once and retry slowly, and the new `cubecli diag tap-holders` / `cubecli diag reclaim` commands help find and clear a stuck holder (#1810).
- Fixed rare block-I/O data corruption or hangs when an I/O returned short (#1825).
- Fixed the lifecycle service hanging on shutdown while waiting on an event subscriber (#1825).
- Fixed creating a sandbox from a snapshot being rejected with "must have exactly one declaration" when the client re-sent the same volumeMounts — which the official E2B SDK does on every create (#1894).

#### Networking & Security

- Fixed two sandboxes listening on the same port and talking to the same remote peer overwriting each other's connection state, breaking one of them (#1915).
- Fixed expired port-mapping sessions occasionally surviving cleanup, inflating session counts (#1914).
- Fixed a leftover session on a port resetting the next new connection on that port; a new connection now replaces it (#1919).
- Fixed IPv6 never working in sandboxes on arm64: the kernel shipped it as a module, but the guest kernel is a single image without modules. PSI is now enabled too, matching x86_64; both are required for Android (redroid) sandboxes, and this also removes intermittent port-binding failures (#1879).

#### Deployment & Upgrade

- Fixed Cubelet logging one error per sandbox on every metrics scrape on cgroup v2 hosts; the unused legacy containerd cgroup monitor is off by default now, and the per-sandbox resource metrics are unaffected (#1869).
- Fixed `cubemastercli` accumulating zombie processes (6500+ observed in one pod over three weeks); a one-time pod restart clears existing zombies (#1860).

#### Other

- Fixed creating a sandbox from a deleted snapshot returning HTTP 500, which SDKs kept retrying forever; it now returns 404 naming the missing template / snapshot (#1868).
- Fixed the Go SDK `Watcher` closing its response body twice under concurrency (#1405).
- The quickstart example pins the `e2b` Python SDK below 2.51: that version calls an endpoint CubeAPI does not provide and fails with 405 (#1909).
- Removed the agent-platform freeze / resume guide and an outdated snapshot timing note from the docs (#1913).

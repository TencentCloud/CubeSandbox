## 2026.11.12 Release v0.8.0

本次发布包含 8 个重大特性，以及多项功能增强与 Bug 修复。共 128 个 PR，来自 46 位贡献者。

### ⭐ 亮点

- **新增JuiceFS COW存储后端（preview）**：基于JuiceFS支持模板跨节点共享、沙箱暂停后跨机恢复及从快照跨机启动。
- **新增FS-only快照能力**：支持仅对沙箱文件系统进行快照，降低存储成本。
- **新增沙箱重启策略**：当沙箱内服务崩溃时，支持自动重启沙箱。
- **调度插件系统**：支持通过CEL、外部调度插件来自定义沙箱在集群中的调度策略。
- **E2B SDK兼容性进一步增强**：支持E2B 2.51.0及以上版本。详情见 E2B API Compatibility and Differences | CubeSandbox
- **沙箱指标与日志采集**：支持在Prometheus、Grafana中查看各项指标。

### 🎯 核心特性

#### 可扩展的调度插件系统 & 调度质量评估框架

- 支持通过内置插件、CEL表达式以及外部gRPC插件来自定义沙箱调度策略，能更加灵活、动态的调整集群的调度行为。
- 新增调度质量评估框架，通过模拟集群拓扑、负载，支持在开发阶段快速衡量某种调度策略的装箱率、碎片、羊群度、调度延迟等指标。

#### JuiceFS COW存储后端支持

- 基于JuiceFS支持模板跨节点共享、沙箱暂停后跨机恢复及从快照跨机启动。支持 Redis、MySQL、TiKV 等多种元数据引擎，以及 MinIO、腾讯云 COS 等对象存储。(#2085)

#### 支持仅对沙箱的文件系统进行快照

- 支持仅对沙箱的文件系统进行快照，降低快照存储成本。用户可以通过FS-only的快照，冷启动新的沙箱。（#2145）

#### 沙箱内服务崩溃时，支持配置自动重启沙箱

- 支持设置沙箱的重启策略，当沙箱内的服务故障时，可以自动在同节点上重启沙箱。

#### 支持沙箱之间通过端口映射互访

- 沙箱之间可以通过其母机端口映射相互访问，基于 TCP 协议的服务都可以通过这种方式实现，不局限于 CubeProxy 的 HTTP/HTTPS/gRPC
- 同母机沙箱通过 hairpin 的方式也支持这种方式通信方式
- 一个沙箱访问另一个沙箱，除了可以通过CubeProxy的HTTP/GRPC方式之外，还可以通过Port-Mapping方式，一种TCP四层通信，支持任何基于TCP的应用，这两种方式都支持同node或跨node的沙箱间访问。

#### Volume框架增强：支持传递用户私有数据

- Volume框架支持传递用户私有数据，可用于支持鉴权，分桶等业务逻辑。(#2136)

#### 沙箱和集群可观测能力提升

- 采集沙箱资源指标及日志，也可以支持扩展更多可视化工具，提供默认看板配置，可灵活对接用户已有的监控、日志运维系统，如Prometheus、Grafana等。为生产化提供统一的可观测，支持运行监测与问题排查手段。（#2183）

### ✨ 功能增强

#### 调度和资源管理

- 新增模板级沙箱 QoS能力：可以设置特定模板创建的沙箱的网络带宽、网络包速率、磁盘吞吐、IOPS上限，避免单个沙箱吃掉宿主机全部资源、影响同机其他沙箱。 (#1174)
- 节点超卖配置设置：支持CLI和Web两种方式设置节点超卖配置，新增节点侧常驻进程ops-agent，承接CubeOps下发的配置指令并修改Cubelet配置文件 (#1870)
- 优化沙箱创建耗时：解决在AMD等厂商的CPU上，由于沙箱资源采集机制读取cgroup，导致沙箱并发创建耗时升高的问题。(#2073)

#### SDK及E2B兼容性

- 新增支持E2B的/v2/sandboxes和/v2/sandboxes/{id}/connect两个接口。使用E2B SDK 2.51.0及以上版本的用户，可以直接创建和连接沙箱，不必再做适配层。(#1800)
- Python/Node/Go SDK新增E2B兼容的Sandbox.fork接口。 (#1649)
- 支持按照快照ID/名称删除快照的能力。(#1987)
- 支持在创建/查询/列表/连接和fork的沙箱响应中查看模版别名。(#2062)
- 支持按照快照名称/ID过滤快照列表。(#2151)
- Python/Node/Go SDK新增Sandbox.is_running的SDK能力。(#2159)

#### 模板与存储

- 制品分发并发数可配置：用户可根据网络带宽&集群规模来调整CubeMaster 向各节点推送 rootfs 制品的并发数 (#1973)
- 优化快照链，同一节点的派生快照共用一个父快照；使用共享内存优化写流程；增加使用快照时的自动预热功能；同时收紧了重启、热升级和 checkpoint 恢复时的校验。 (#1996)
- cubemastercli tpl delete 新增 --force 选项：支持清理卡住或处于异常构建状态的模板删除任务，强制删除模板元数据及模板在各节点上的制品副本。(#2038)
- 支持通过SDK/API创建模版时指定存储后端 (#2039)
- 模板支持指定运行用户：建模板时可以指定沙箱以哪个用户（UID或用户名）来运行。 (#2072)
- 优化 ext4 镜像的存储和下载. (#1885)

#### 生命周期和控制面

- vsock连接管理优化 (#1925)
- 优化沙箱详情查询接口，减少查询开销。 (#2092)

#### 网络

- arm/x86 的 guest kernel 日志输出将会统一重定向到 virtio-console 以降低冷启动开销 (#1992)；

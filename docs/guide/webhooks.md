# Webhooks

CubeAPI can deliver sandbox lifecycle events to one or more HTTP endpoints. Use
webhooks when an orchestration system, alerting service, or audit pipeline needs
to react to sandbox state changes without polling CubeAPI.

Webhook delivery is asynchronous. Sandbox API handlers enqueue an event and
return through the normal control path; slow or unreachable receivers do not
block sandbox creation, pause, resume, or deletion.

## Supported Events

The current CubeAPI webhook integration emits these sandbox lifecycle events:

| Event | Trigger | Extra fields |
| --- | --- | --- |
| `sandbox.created` | `POST /sandboxes` succeeds | `template_id` |
| `sandbox.paused` | `POST /sandboxes/{sandboxID}/pause` succeeds | |
| `sandbox.resumed` | `POST /sandboxes/{sandboxID}/resume` succeeds | |
| `sandbox.deleted` | `DELETE /sandboxes/{sandboxID}` succeeds | |

## Configuration

Start `cube-api` with `CUBE_API_WEBHOOKS` set to a JSON array. Each entry defines
one endpoint.

```bash
export CUBE_API_WEBHOOKS='[
  {
    "url": "http://127.0.0.1:9000/webhook",
    "events": [
      "sandbox.created",
      "sandbox.deleted",
      "sandbox.paused",
      "sandbox.resumed"
    ],
    "secret": "dev-secret",
    "timeout_secs": 3,
    "max_retries": 3
  }
]'
```

Endpoint fields:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `url` | string | Yes | Full HTTP or HTTPS callback URL. |
| `events` | string array | No | Event names to subscribe to. Empty or omitted means all events. |
| `secret` | string | No | HMAC-SHA256 signing secret. Omit to disable signatures. |
| `timeout_secs` | integer | No | Per-attempt HTTP timeout. Default: `3`; minimum effective value: `1`. |
| `max_retries` | integer | No | Retries after the initial attempt. Default: `3`. |

Invalid JSON disables webhook delivery and logs a warning. Endpoints with empty
URLs are ignored.

## Payload

CubeAPI sends each event as an HTTP `POST` with `Content-Type:
application/json`.

Example `sandbox.created` payload:

```json
{
  "event": "sandbox.created",
  "timestamp": "2026-06-30T14:49:20.879472593+00:00",
  "sandbox_id": "c07539a1d61a4544b0c075a9b236871a",
  "template_id": "tpl-7c41d76bd0ea4457a2ccb470"
}
```

Example `sandbox.deleted` payload:

```json
{
  "event": "sandbox.deleted",
  "timestamp": "2026-06-30T14:49:48.368169185+00:00",
  "sandbox_id": "c07539a1d61a4544b0c075a9b236871a"
}
```

Every payload includes:

| Field | Description |
| --- | --- |
| `event` | Event name. |
| `timestamp` | RFC 3339 event timestamp generated by CubeAPI. |
| `sandbox_id` | Sandbox identifier. |

Additional fields may be included when CubeAPI has context, such as
`template_id` for `sandbox.created`.

## Signature Verification

When `secret` is set, CubeAPI signs the raw request body and sends these headers:

| Header | Description |
| --- | --- |
| `X-Cube-Event` | Event name. |
| `X-Cube-Timestamp` | Unix timestamp in seconds. |
| `X-Cube-Signature` | `sha256=<hex hmac>`. |

The signed string is:

```text
<X-Cube-Timestamp>.<raw request body>
```

Python verification example:

```python
import hashlib
import hmac


def verify(secret: str, timestamp: str, body: bytes, signature: str) -> bool:
    signed = timestamp.encode("utf-8") + b"." + body
    expected = "sha256=" + hmac.new(
        secret.encode("utf-8"), signed, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(signature, expected)
```

Receivers should reject invalid signatures with `401 Unauthorized`.

## Retry Behavior

CubeAPI treats non-2xx HTTP responses and transport errors as delivery failures.
Failed deliveries are retried with exponential backoff starting at 200 ms until
`max_retries` is exhausted. Failures are logged by CubeAPI, but the original
sandbox API request is not rolled back.

## Runnable Receiver

The repository includes a minimal receiver:

```bash
cd examples/webhook-receiver
WEBHOOK_HOST=0.0.0.0 WEBHOOK_PORT=9000 WEBHOOK_SECRET=dev-secret \
  python3 receiver.py
```

The receiver prints each accepted callback as JSON and verifies
`X-Cube-Signature` when `WEBHOOK_SECRET` is set.

## Local dev-env Verification

In the `dev-env` VM workflow, CubeAPI runs inside the VM and the receiver runs on
the host. Use the QEMU gateway address `10.0.2.2` from the VM to call back to the
host receiver:

```bash
export CUBE_API_WEBHOOKS='[{"url":"http://10.0.2.2:9000/webhook","events":["sandbox.created","sandbox.deleted","sandbox.paused","sandbox.resumed"],"secret":"dev-secret","timeout_secs":2,"max_retries":1}]'
```

After restarting `cube-api`, create a sandbox and trigger lifecycle operations:

```bash
curl -X POST http://127.0.0.1:13000/sandboxes \
  -H 'Content-Type: application/json' \
  -d '{"templateID":"<template-id>","timeout":300}'

curl -X POST http://127.0.0.1:13000/sandboxes/<sandbox-id>/pause
curl -X POST http://127.0.0.1:13000/sandboxes/<sandbox-id>/resume \
  -H 'Content-Type: application/json' \
  -d '{"timeout":300}'
curl -X DELETE http://127.0.0.1:13000/sandboxes/<sandbox-id>
```

The receiver should print `sandbox.created`, `sandbox.paused`,
`sandbox.resumed`, and `sandbox.deleted`.

## Alerting Integrations

### Generic HTTP Alerting

Most alerting systems accept a JSON `POST`. Point `url` to the alerting ingest
endpoint and subscribe only to the events that should generate alerts. If the
receiver requires a custom shape, run a small adapter service that verifies the
Cube signature and transforms the payload before forwarding it.

### WeCom Robot

WeCom group robots expect a different JSON body from CubeAPI's event payload.
Use a small adapter as the webhook receiver:

1. Receive CubeAPI webhook callbacks.
2. Verify `X-Cube-Signature` with the configured secret.
3. Format a WeCom message, for example `Sandbox c075... was deleted`.
4. POST the formatted body to the WeCom robot URL.

Example forwarded body:

```json
{
  "msgtype": "text",
  "text": {
    "content": "CubeSandbox event sandbox.deleted for c07539a1d61a4544b0c075a9b236871a"
  }
}
```

Do not configure the WeCom robot URL directly as `CUBE_API_WEBHOOKS.url` unless
the robot accepts CubeAPI's payload and signature headers as-is.

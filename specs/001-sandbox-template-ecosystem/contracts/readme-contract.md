# Contract: Example README

Each example README must let a new user understand, build, run, validate, and clean up the example without inspecting unrelated examples.

## Required Sections

1. Title and short summary.
2. Link to localized README when present.
3. What this example demonstrates.
4. Prerequisites.
5. Template creation or acquisition.
6. Environment variables.
7. Install dependencies.
8. Run the minimum example.
9. Expected output.
10. Resource guidance.
11. Security and network notes.
12. Known limitations.
13. Troubleshooting or links to relevant docs.
14. Cleanup.

## Content Rules

- Commands must be copyable and use project-standard environment variables where possible.
- Expected output must be specific enough to compare against actual results.
- Secret values must use placeholders.
- External services and network requirements must be explicit.
- Exposed ports and public URL behavior must be documented when relevant.
- The README should explain when to choose this example instead of nearby examples.

## Localized README

When the project maintains a localized counterpart for comparable examples, the localized README should cover the same runnable flow and limitations. It does not need to be word-for-word identical, but it must not omit required safety or validation information.

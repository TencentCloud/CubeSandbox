几百个沙箱怎么共享一张网卡

一篇讲 CubeVS，CubeSandbox 的网络数据面。几百个沙箱挤在一台物理机上，要同时上网、要互相隔离、要按策略控制访问——传统做法是堆 iptables 规则，规则一多就慢。CubeVS 换了一个思路：把"规则比对"换成"查表放行"，直接跑在内核的 eBPF 里。我们从头拆。

一、问题：规则越来越多，网就越来越慢

先想清楚物理现实：一台物理机上一块网卡，几百个沙箱各有一个"假的"私有 IP。每个沙箱要上网，出去必须伪装成物理机 IP（NAT）；外面要访问沙箱里的服务，又得把流量翻译回那个假 IP。同时沙箱之间必须隔离，还得按策略控制"谁能访问什么"。

传统方案是给每个沙箱配一套 iptables 规则（NAT + filter）。几百个沙箱就是几千条规则——每个包进出都要逐条比对，规则越多越慢；而且配置一下就是几秒，规则之间还会互相打架，运维噩梦。问题的本质是："规则比对"的复杂度是 O(规则数)，它不该随沙箱数量线性增长。

换个思路：如果我们不改"规则"，而是改"表"呢？
把策略做成一张哈希表，每个包查一次表——查表时间是 O(1)，与规则数量无关。这就是 eBPF 的查表放行。

二、核心思想：把"逐条比对规则"换成"一次哈希查表"

理解 CubeVS 只需要理解一件事：它把网络策略做成了"查表放行"，而不是"逐条比对规则"。

实现上，策略存在 eBPF 的 map（内核里的哈希表）里；一段 eBPF 程序挂在内核网络通道的必经之路上，每个包进来先查这张表——查到了就放行 + 改地址，查不到就拦下。规则再多，也只是表里的多几行记录，查表时间恒定为一次哈希查找。而且这一切发生在内核数据路径上，没有用户态介入，没有 netfilter 钩子，单个包的处理是微秒级。

"外面访问沙箱"怎么处理？也是查表——查的是另一张反方向的会话登记表：出向流量经过时登记一笔"谁从哪个端口出去了"，回包时按登记反向翻译回假 IP。没有登记的回包，不翻译，直接放主机栈。这套"来去都认账"的机制让沙箱间流量天然隔离：没有出向会话，就永远等不到对应的入向包。隔离不是靠"挡住"，而是靠"不认"。

三、三条数据路径，各管一段

三条路径都只干一件事：查表 + 改地址 + 投递。没有一条路径去"逐条比对规则"。有趣的是它们的挂载点也不同：出门和回家分别挂在 TAP 虚拟网卡和物理网卡两个方向，访客路径挂在本地网关——三个 eBPF 程序，三个挂载点，职责互不重叠，各管一段数据流。

四、最精巧的设计：DNS 学习

有一个问题让纯 IP 白名单几乎没法用：管理员允许沙箱访问 *.example.com，但沙箱实际连接的是这个域名的 IP——而 IP 会变，管理员没法预先填 IP。传统方案只能把域名流量全部交给上层代理（L7），每个请求过一遍，慢。

CubeVS 让门禁系统"自己学"：

① 沙箱发出 DNS 查询（请求 www.example.com 的 IP） 如果查询的域名在允许名单里 → 在"登记簿"上记一笔 ② DNS 响应回来 → 门禁只认登记簿里对应的响应 把响应的 IP 自动写进允许名单（带有效期，跟 DNS TTL 走） ③ 之后沙箱直连这个 IP → 不再走代理，直接放行

这里最关键的是安全性："只认登记过的响应"。沙箱不能伪造一个 DNS 响应，把自己想要的 IP 灌进名单——能进名单的，只有它已经获准查询的域名的真实应答。于是"放行域名"这个语义，被精确落实成了"放行该域名的真实 IP"，而 IP 的变动由 DNS 响应自动跟随。一个本来需要 L7 代理才能做的事，在 L4 查表里就完成了，代价仅是拦截一下 DNS 流量。

五、谁来打扫：会话与名单的回收

所有表都在内核内存里，有容量上限，必须有清理机制。CubeVS 的做法是后台定期"大扫除"（reaper.go）：按协议超时判断逐条删除过期记录——TCP 会话超时、UDP 30 秒没回包、180 秒没再发包、DNS 学来的 IP 过了 TTL。任何查表系统都必须回答"表满了怎么办、表脏了怎么办"，这里用"周期性回收"这个最直白的答案。

另外还有一层"运维管家"：network-agent 进程负责每个沙箱虚拟网卡（TAP）的创建和销毁、端口分配、策略下发。沙箱创建时它插网卡，销毁时拔网卡，策略随沙箱生、随沙箱灭——没有"僵尸规则"残留。eBPF 程序处理"快"，但"规则从哪来、随什么清理"这件事，必须有这么个配套的进程管理，否则表里的记录会漏一辈子。

六、收束

问题设计关键权衡
规则随沙箱数线性膨胀eBPF map 查表，O(1)快，但要配套回收机制
沙箱间隔离出向登记、入向认账隔离靠"不认"而非"挡"
域名白名单遇到动态 IPDNS 学习：只认登记过的响应L4 完成本该 L7 的事
表会满、会脏reaper 定期回收简单直白
规则随沙箱生灭network-agent 管理 TAP 与策略无僵尸规则
一句话带走 CubeVS 用 eBPF 把 NAT 和访问控制做成"查表放行"：出门查白名单、回家按会话登记翻译、访客按端口映射投递，外加"DNS 学 IP"和"后台大扫除"两个小机制——几百个沙箱的虚拟网络，就在这张表上转起来了。

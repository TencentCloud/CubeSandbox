01 项目概览

CubeSandbox 是一个多语言（Go + Rust + Web）Monorepo 沙箱服务。所有组件构建在 Docker builder 容器中完成（make 目标驱动），产物输出到 _output/bin/。

定位

面向 AI Agent 场景专门构建的基础设施。不只支持"LLM 调用工具 → 沙箱执行 → 返回结果"的经典闭环，也支持在沙箱内托管长时运行的 Agent 与有状态服务（常驻开发环境、Web 服务、数据库等）。

隔离模型

每个沙箱是一个在 KVM MicroVM 中运行独立 Linux 内核的沙箱，不存在共享内核的逃逸面；出站流量全部经 CubeEgress L7 代理，域名必须显式放行（零信任出网）。

性能手段

预快照模板 + RustVMM 恢复路径实现毫秒级冷启动；内核共享与 CoW 快照（FICLONE，O(1)）让单机可运行数千实例，单沙箱额外开销 <5MB。

生态兼容

对外暴露 E2B 兼容的 REST API 与 SDK；替换一个环境变量（API URL）即可从 E2B 云无缝切换，无需改动业务代码。

组件语言矩阵

Go 控制面与节点编排

CubeMaster（调度器）、Cubelet（节点代理）、CubeOps、cube-lifecycle-manager、network-agent、CubeNet/cubevs（eBPF 控制面）、CubeDB。

Rust 数据面核心

CubeAPI（Axum 网关）、CubeShim（Shim v2）、hypervisor（RustVMM）、cubecow（快照引擎）、agent（沙箱内 guest agent）。

OpenResty + Lua 数据面代理

CubeProxy（反向代理/路由）、CubeEgress（L7 出向安全代理）。

C (eBPF) 内核态网络

CubeNet 的三个 BPF 程序（CO-RE）：from_cube / from_world / from_envoy。

02 设计原则

这六条原则决定了整个系统的结构形态，理解它们就能理解后面所有组件的职责划分。

Agent 优先

生命周期语义、SDK 形态、自动暂停/恢复、极速克隆/回滚等特性为 Agent 工作负载定制，而非通用 VM 平台。

硬件隔离

每沙箱独立 KVM MicroVM + 独立内核；叠加 eBPF 网络隔离，隔离级别高于容器、等同物理机。

毫秒级启动

预快照模板 + RustVMM 恢复路径（而非冷启动引导），冷启动 <60ms、50 并发下 P95 90ms。

零信任出网

所有出站流量经 CubeEgress L7 MITM 代理，域名白名单放行；私网/链路本地地址段被 CubeVS 默认拒绝。

无状态控制面

CubeAPI / CubeMaster 不保存本地状态，Redis 是元数据与生命周期事件的唯一可信源，可水平扩容。

高效存储

CubeCoW 借助内核 FICLONE ioctl 在 XFS reflink 上实现 O(1) 快照与克隆，零数据拷贝。

03 整体架构

系统按"控制面 / 数据面"分层：控制面无状态、依赖 Redis 协调，可横向扩展；数据面节点本地化，负责 VM 生命周期、存储、网络与安全策略执行。

核心循环
  • 启动引导：HGETALL lifecycle:meta 全量加载 → XGROUP/XREADGROUP 消费事件流增量。
  • 自动暂停（sweeper）：idle = now − max(LastActiveMs, CreatedAt) 超过 timeout_seconds 且 auto_pause → SETNX 状态锁 → 调 CubeMaster Pause → 广播 "paused"；否则超时 kill。

两种路由模式
  • Host 模式：从 Host 头解析 <port>-<sandbox_id>.<domain> → resolve_backend 查后端 IP/端口 → 渲染 maskRequestHost（envd 49983 豁免）→ balancer 选上游。

  • 自动恢复门禁（sandbox_state.lua）：rewrite 阶段查状态字典——paused → 捕获子请求触发 CLM 恢复并阻塞等待；pausing → 503 Retry-After；killing/killed → 410。
  • envd 流式端点白名单（Process/Start|Connect、Filesystem/WatchDir）关闭缓冲。

透明 L7 出向安全代理
▶

部署在每台主机上的透明 L7 出网代理，通过 TPROXY 拦截每一个出站 HTTP/HTTPS 请求：域名过滤、凭据注入、访问审计。沙箱信任 CubeEgress 签发的根 CA（预置于模板），实现透明 TLS 检查。

关键文件
CubeEgress/nginx.conf（transparent listen）
lua/access_phase.lua（决策 + 注入主逻辑）
lua/policy.lua（shared_dict 策略存储）
lua/admin.lua（/admin/v1/ 管理 API）
lua/cert_signer.lua（动态叶子证书）
核心机制
  • TPROXY：nginx 补丁为 listen 增加 transparent 关键字（IP_TRANSPARENT），accept 后用 getsockname() 取真实目的地址。
  • 决策（access_phase.lua _M.decide）：按 sandbox_ip 查策略，规则首匹配生效（sni/host/method/path/scheme）；bootstrap 未就绪默认拒绝（fail-closed）。
  • 凭据注入：inject{header, secret, format} 写入请求头（先 clear_header 防伪造），审计只记 secret_ref 指纹。
  • 动态证书：ssl_certificate_by_lua_block 用根 CA 按 SNI+目的 IP 签发叶子证书；上游 proxy_ssl_verify on。
05 一次 Sandbox.create() 的完整请求链路

从 SDK 调用到沙箱就绪，请求依次穿过控制面与数据面的每一层。同步路径只到"调度完成"，沙箱实际就绪通过生命周期事件异步确认。

1
Client / SDK
POST /sandboxes（兼容 E2B）
携带 template、timeout、lifecycle（on_timeout / auto_resume）、env_vars、network 等参数。
2
CubeAPI（Rust/Axum）
鉴权 + 参数校验 → HTTP 转发 CubeMaster
中间件做鉴权回调与限流；services/sandboxes.rs 校验环境变量黑名单、出站域名；错误映射 130404→404 / 130409→409 / 130490→503。
3
CubeMaster（Go）
调度器选择目标节点
pkg/service/sandbox/sandbox_run.go 触发 scheduler.Select：预选 → 并行 filter（cpu/mem/disk/实时创建上限/模板本地性）→ 加权打分 → 随机挑选；失败走 BackoffSelect。本地缓存（localcache/instancecache）提供节点与模板分布数据。
4
CubeMaster → Cubelet（gRPC）
RunCubeSandbox
pkg/cubelet/actions.go 经连接池（grpcconn）发起 CubeboxMgr.Create，请求携带 volumes、containers、exposed_ports、runtime_handler、instance_type、network_type、cube_network_config（L7 出站规则）。
5
Cubelet（Go）
Workflow：prepare rootfs → 交给 containerd
services/cubebox/local.go 驱动 workflow：createid 分配 → CubeCoW 从模板卷克隆 rootfs（FICLONE）与内存快照 → storage/cgroup/network 准备 → containerd.NewContainer + WithRuntime(io.containerd.cube.rs) 创建容器 → Task 启动驱动 shim。
6
CubeShim（Rust，Shim v2）
Create + Start → 启动 VM
task_srv.rs 收到 containerd Task 请求 → sb.create_sandbox()：launch_vmm（hypervisor 库启动 VMM 线程）→ create_vm + restore_vm（从模板内存快照恢复）→ 连接 guest agent → agent.create_sandbox → watch_oom / monitor_vm。vsock 就绪后回 Task 已启动。
7
Cubelet → network-agent → CubeVS / CubeEgress
AddTAPDevice + AttachFilter + 策略下发
network-agent 创建/直通 TAP fd（SCM_RIGHTS），CubeVS 注册 TAP 并挂 from_cube TC 过滤器；把 allow/deny/DNS 域名推入 eBPF Map；L7 egress 规则推送到 CubeEgress admin API。
8
CubeMaster → Redis → CLM → CubeProxy
发布生命周期事件，注册路由，返回结果
CubeMaster pkg/lifecycle/store.go 写 meta（HSET）+ XADD events；CLM 消费后把 sandbox 路由/状态推送给所有 CubeProxy；最终 201 返回 sandbox_id 与元数据给客户端。CubeProxy 路由表就绪后，客户端即可通过 <port>-<sandbox_id>.<domain> 或 /sandbox/<id>/<port> 访问沙箱内服务。
执行链路（数据面）：沙箱内代码执行时，agent（vsock ttRPC）接收宿主侧 ExecProcess/流式 IO 指令，运行 OCI 容器；沙箱进程的 IO 经 virtio + agent 流式转发回 CubeProxy/客户端。
06 沙箱状态机与自动暂停 / 恢复

沙箱是系统的核心运行单元。五个状态 + 两个驱动参数（timeout 与 on_timeout）构成完整的生命周期管理。CLM 是自动化的中枢。

running运行中 · 占用 CPU/内存
timeout & on_timeout=pause
（空闲超时）
pausing瞬时 · 保存 VM 快照中
快照完成
paused内存落盘 · 零 CPU/内存占用
running
timeout & on_timeout=kill
或显式 kill()
terminated不可恢复
paused
kill() / DELETE
（内部先恢复再销毁）
terminated

自动暂停 / 恢复的完整时序

1
CubeMaster
创建沙箱时登记生命周期 meta
写 HSET cube:v1:shared:sandbox:lifecycle:meta（timeout_seconds / auto_pause / auto_resume）+ XADD events。CLM 启动时 HGETALL 全量引导 registry，之后 XREADGROUP 增量消费。
2
CLM · sweeper
扫描空闲沙箱，触发自动暂停 / 超时销毁
idle = now − max(LastActiveMs, CreatedAt)；auto_pause=true → tryPause（SETNX 状态锁防并发 → 通知 CubeProxy → CubeMaster Pause RPC → 写 paused 并广播）；否则超时 kill（KillReasonTimeout）。BootstrapWarmup 防止重启误暂停。
3
CubeMaster → Cubelet → CubeShim
执行暂停（内存快照落盘）
Cubelet task.Pause → shim sb.pause_vm()：把 VM 内存写快照到 PAUSE_VM_SNAPSHOT_BASE/{id}，随后 VmPauseToSnapshot。paused 状态物理上释放 CPU/内存。
4
CubeProxy（数据面）
请求到达 paused 沙箱 → 触发恢复
rewrite 阶段查状态字典发现 paused → 捕获子请求 /_sidecar_resume → CLM resumer：并发合并为单次 callCubeMasterResume → waitForRunning（轮询状态）→ 回推 running 给 CubeProxy → 阻塞中的请求继续转发，客户端无感知。
5
CubeShim
从快照恢复 VM
sb.resume_vm() → VmResumeFromSnapshot；恢复成功后获得全新 timeout 计时窗口（"恢复 → 使用 → 再次空闲 → 再次暂停"循环无缝持续）。
删除 paused 沙箱：DELETE 会先在内部恢复运行时状态（最多 5 秒预算）再走正常销毁，不触发 resumed 生命周期事件；失败返回 409（资源准入）/ 503（操作未完成，带 Retry-After）。
暂停资源释放（quota.paused_resource_release_ratio）：默认 0 = 暂停沙箱保留完整调度配额（恢复必有保障）；=1 全部释放（最大化密度、恢复尽力而为）；0~1 之间折中。节点级配置在 Cubelet/config/config.toml。恢复时触发本地实时准入检查，不满足返回 409 带配额诊断。
07 存储逻辑：CubeCoW 快照引擎

所有 rootfs 与内存卷操作（创建、克隆、快照、删除）由 Cubelet 通过 CubeCoW 完成。核心是内核 FICLONE 提供的 O(1) reflink 语义。

阶段做什么技术
模板创建OCI 镜像 → Buildkit → rootfs + 冷启动一次 → 内存快照 → 注册为模板（只读基础）Buildkit + CubeCoW
沙箱启动Cubelet 克隆模板的 rootfs 与内存卷（O(1) 零拷贝），CubeShim 从内存快照恢复 VMFICLONE + restore_vm
增量快照仅写入匿名（脏）内存页，未变更页 reflink 共享上一快照脏页追踪 + reflink
回滚 / 克隆回滚 = 丢弃当前状态挂载历史快照；克隆 = 从任意快照 fork 出独立环境（分叉探索）RollbackSandbox / CommitSandbox
 
模板（只读基础）
  └── FICLONE ──→ 沙箱 rootfs 卷 (CoW)
                      ├── FICLONE ──→ 快照 A
                      ├── FICLONE ──→ 快照 B（只存脏页）
                      └── FICLONE ──→ 克隆 1、克隆 2、…（可从任意快照 fork）

扁平快照模型

快照之间无依赖链，删除任一快照不影响其他快照，crash-safe 且可独立挂载。

应用层快照（AppSnapshot）

Cubelet 提供 AppSnapshot RPC：创建沙箱 → 运行到目标状态 → 截图（内存+文件系统）→ 销毁，产物即新的模板/快照。

Volume 框架

兼容 E2B 标准；允许以插件形式自定义后端存储（CubeMaster pkg/volume/plugin/{binary,rpc} + refcount），Volume 独立生命周期、可跨沙箱共享。

运行中快照

CommitSandbox 对运行中沙箱打快照，RollbackSandbox 回滚到任意已提交快照（CubeShim rollback_vm：VmDelete + VmResumeFromSnapshot，避免写盘）。

08 网络逻辑

三层网络栈：CubeVS（内核态转发与策略）、CubeEgress（L7 出向安全）、CubeProxy（L7 入向路由）。整个数据面无 iptables / 无网桥 / 无 OVS。

8.1 出站流量路径（沙箱 → 外部）

1
沙箱进程
发送报文，源 IP = 169.254.68.6（固定内部地址）
默认网关 169.254.68.5 由 from_cube 现场构造 ARP 应答（ARP 代理）。
2
from_cube（TAP TC ingress）
策略 → 网关 → SNAT → 会话
目标为网关 → 重定向 cube-dev 交宿主机协议栈；被策略标记需 L7 检查的流量 → 重定向 cube-dev 走 CubeEgress；否则：策略评估 → DNS 拦截（域名规则学习）→ 创建/更新会话（egress_sessions + ingress_sessions）→ SNAT（jhash(sandbox_ip) % 4 确定性选 IP，端口从 30000 起水位线分配，自旋锁防碰撞）→ 重定向到宿主机网卡。
3
CubeEgress（L7，可选路径）
透明代理：域名过滤 + 凭据注入 + 审计
TPROXY 监听 192.168.0.1:8080/8443（transparent），决策规则首匹配（sni/host/method/path/scheme），未就绪 fail-closed；通过 ssl_certificate_by_lua 按 SNI 动态签发叶子证书完成 TLS 检查；响应经 cube-dev（from_envoy 保留真实远端源 IP）回到沙箱。

8.2 入站流量路径（外部 → 沙箱）

1
from_world（宿主机网卡 TC ingress）
会话反向 NAT / 端口映射
查 ingress_sessions 命中 → 重建沙箱侧五元组反向 DNAT → 重定向 TAP；未命中则查 remote_port_mapping[host_port] → DNAT 到沙箱监听端口。
2
CubeProxy（L7 路由）
把对 <port>-<sandbox_id> 的访问路由到沙箱后端
Host 模式解析 Host 头，Path 模式解析 /sandbox/<id>/<port>/；结合状态门禁支持自动恢复、503 Retry-After、410 Gone。

8.3 会话跟踪与 DNS 学习

双 Map 会话跟踪

egress_sessions（沙箱侧五元组 → 完整 NAT 状态）与 ingress_sessions（外部侧五元组 → 反向重建）。TCP 11 状态机按协议状态调整超时（ESTABLISHED 3h，SYN_SENT 1min…）；Go 回收器每 5s 清理，占用超 80% 告警。

DNS 学习式域名策略

from_cube 拦截查询（dns_allow LPM 精确/通配匹配 + dns_query_track 记录）；from_world 在响应时提取 A 记录写入 allow_out_v2（TTL 过期）。仅当沙箱配置域名规则才开启（dns_policy_flags 总闸门），否则零开销。

端口分段规划

10000–19999 宿主机临时端口；20000–29999 CubeProxy 访问沙箱端口；30000–65535 SNAT 源端口。避免子系统间冲突。

策略优先级

网关 > allow_out_v2 > deny_out > 默认放行；始终拒绝私网/链路本地段。LPM-trie 线速执行，每沙箱 Hash-of-Maps 隔离，更新不干扰他人。
